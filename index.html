RE:POINT — 完整服务设计方案

Adaptive Distributed In-store Service Support System for Older Customers in Reuse Shops

面向老年顾客的二手商店自适应分布式服务支持系统

这次不再以效果图和实体设施的外观为主，而是深入设计整套服务系统，包括服务如何运行、顾客如何参与、工作人员如何响应、不同店铺如何适配，以及最终如何制作原型和进行学术验证。

以 IKEA Info Point 的系列化服务设施、Deskless Service Model 的分布式人员服务机制，以及 A Better A&E 的信息支持方式作为概念参考。

01Design Brief｜设计任务书

项目 内容
项目名称 RE:POINT
设计类型 Spatial Service Design / Product-Service System
研究对象 2nd STREET 实体二手商店
主要用户 65岁及以上顾客
设计对象 店内信息与服务支持机制
设计目标 提升信息理解、自主行动及服务可达性
设计策略 自适应、分布式、模块化、连续性
设计限制 尽量利用现有空间与人员，不依赖个人智能手机
最终成果 服务系统、实体交互原型、空间配置模型、实施指南

核心设计命题

如何通过重新组织实体二手商店中的信息、空间和人员服务，使老年顾客能够在不同服务阶段获得与自身需求相匹配的支持？

这里的设计对象不再是单个信息载体，而是顾客获得服务的方式。

02Research Translation｜从研究发现到设计策略

结合你之前对9家店铺的观察、问卷及访谈，将现有研究转化为具体的设计介入。

前期研究发现 服务层面的问题 设计策略
入口信息不足 顾客难以建立整体认知 入口服务初始化
商品小分类难以理解 信息支持与任务需求不匹配 分层信息服务
跨楼层引导不连续 不同空间节点之间缺少衔接 分布式连续支持
休息区及厕所位置难以获知 基础服务信息不易获取 就近服务查询
出售流程不清楚 顾客难以预测下一步行动 服务阶段可视化

员工协助机制则属于需要进一步验证的设计机会，而不是已经由现有数据充分证明的研究结论。

03Service Concept｜核心服务概念

RE:POINT 的核心是将传统的集中式、被动式信息服务，转变为分布式、按需获取的服务支持。

现有服务模式 顾客自行寻找信息，遇到困难后寻找工作人员。
RE:POINT 服务模式 顾客在需求发生的位置获得适当的服务支持。
W — 入口节点 I — 信息节点 A — 协助节点 S — 出售节点

整个系统由四个设计层构成。

01
Service Logic · 服务逻辑层 根据顾客需求调整服务支持程度
↕
02
Touchpoint Network · 触点网络层 将不同功能的服务节点分布在店内
↕
03
Human Support · 人员服务层 建立顾客与工作人员之间的协作机制
↕
04
Configuration System · 配置系统层 根据店铺类型调整节点数量、功能及位置

04Adaptive Service Mechanism｜自适应服务机制

自适应并不意味着必须使用AI，也不意味着系统自动判断顾客是否年老或能力不足。

在硕士阶段，自适应主要通过顾客自主选择、信息逐层展开和服务模式切换来实现。

三个服务支持层级
LEVEL 01 Self-service｜自主服务 顾客自主浏览、寻找商品和完成任务，不需要额外干预。
LEVEL 02 Guided Service｜引导服务 顾客获取更详细的分类信息、空间位置及分步骤行动指引。
LEVEL 03 Assisted Service｜协助服务 顾客主动提出需求，由工作人员提供有针对性的帮助。

服务运行规则

触发条件 系统响应
顾客熟悉店铺 不主动干预
顾客不知道商品位置 提供区域及分类引导
顾客需要更详细的信息 展开任务相关信息
顾客无法独立完成任务 提供人工协助入口
员工暂时无法响应 告知等待方式或替代支持
顾客已经解决问题 返回自主服务模式

这一机制的设计价值在于：既不强制老年顾客接受帮助，也不假设所有顾客都能够完全独立地完成任务。

11. Prototyping Strategy｜原型制作计划

我建议最终制作三个层级的原型。这部分才是你真正需要投入设计和制作的内容。

Prototype 01 — Spatial Configuration Model 空间配置原型，建议采用1:50比例。 制作三种店铺的可重组空间模型，包括货架、柜台、楼梯和四种可移动的服务节点模型。用于研究节点的位置、组合及覆盖范围。 软件：Rhino / SketchUp / Illustrator　制作：激光切割、3D打印
Prototype 02 — Full-scale Interactive Prototype 1:1实体交互原型。 重点制作 Information Point，包括模块化外壳、显示界面、操作区域及协助请求功能。 Welcome Point 可以使用低保真实体模型，Assistance Point 则可以通过现有家具及员工角色扮演实现。 软件：Rhino / Figma　制作：木工、纸板、触摸屏
Prototype 03 — Service Experience Prototype 完整服务体验原型。 在学校搭建局部模拟店铺环境，设置入口、商品货架、信息服务节点和员工协助区域。参与者可以真实地进入空间、移动、操作设备、提出需求及完成任务。 方法：Experience Prototyping / Bodystorming / Wizard of Oz

原型之间的关系

1:50 空间模型 验证服务节点应该在哪里
1:1 交互设施 验证顾客如何使用服务节点
完整服务体验模拟 验证不同触点及人员如何协作
Service Evaluation 根据实验结果迭代服务系统

12. Evaluation Design｜学术验证方案

为了避免研究范围过大，不建议同时验证四种服务节点、三种店铺及所有服务任务。

建议选择单层综合店作为代表性空间，以寻找指定商品为核心实验任务。

研究问题

RQ 研究问题
RQ1 老年顾客在完成店内购物任务时，需要在哪些阶段获得何种信息支持？
RQ2 如何将不同的信息需求转化为分布式、自适应的服务节点？
RQ3 新服务系统能否改善老年顾客的信息理解及任务完成体验？

实验条件

CONDITION A 现有服务模式 现有标识、商品分类信息、常规人工服务。
CONDITION B RE:POINT 服务模式 分布式信息支持、分层引导、按需人工协助。

采用相同空间环境、等难度任务和统一的员工响应规则。若采用被试内实验，应平衡两种条件的体验顺序，降低学习效应。

评价指标

评价维度 测量方式
信息理解 信息理解测试正确率
任务完成 任务成功率
行动效率 完成时间、错误转向次数
信息获取 重复查询次数
服务可达性 获取有效帮助所需时间
自主性 独立完成任务的情况
行动信心 Likert量表
服务体验 实验后问卷与访谈
员工负荷 协助时间及响应次数，作为探索性指标

实验结果需要结合定量数据和行为观察进行分析，而不是只询问参与者是否喜欢设计方案。

17. Scope Control｜硕士研究范围控制

整套RE:POINT方案的完整度已经比较高，但如果全部实施，工作量很可能超过一个人的硕士研究范围。

因此，我建议采用 Full System Design + Focused Prototype + Focused Evaluation 的策略。

层级 研究范围
系统设计 完整设计四种服务节点及协作机制
产品设计 深入设计 Information Point
实体制作 一个高保真节点，其他节点低保真模拟
空间设计 三种店铺的概念配置模型
实验验证 一种店铺、一项核心购物任务
延伸研究 出售服务、跨楼层支持、复杂员工协作

其中，Sell Point、移动员工服务机制以及实时进度反馈系统都可以作为系统延伸概念，不需要在硕士阶段全部实现。

总结

我认为 RE:POINT 最有潜力的地方，在于它能够同时体现四种设计能力：

  • Service Design： 服务模式与人员协作机制。
  • Spatial Design： 分布式服务节点及空间配置。
  • Product Design： 模块化实体服务设施。
  • Interaction Design： 信息交互及分层服务支持。

但需要明确，目前这是一套完整的概念设计方案，并非已经验证的最终研究成果。服务节点的必要性、员工响应机制、实体尺寸及配置数量都需要进一步研究。

尤其要避免为了体现设计成果的丰富程度，而强行增加服务设施。

最终你真正需要设计的不是四台机器，而是一套能够根据顾客需求和店铺条件灵活配置的服务系统。 实体设施只是这套系统的物理表现，服务体验及其有效性才是硕士研究的核心贡献。
